# Agent Note: 项目管理插件开发文档

Status: proposed

[English](2026-11-25-project-management.md) | 中文

## 问题

海亮素质教育共享平台需要统一管理面向政府推进的项目，覆盖接洽、签约、交付与运营。当前个人部署为每个账号提供一个固定工作空间，不能创建共享的项目工作空间。本开发文档统一规定元数据、目录创建、共享可见性，以及受影响的会话和文件操作，供接手开发者实施。

## 方案

### 1. 范围与决策状态

本文是尚未实施的开发方案。下文的包名、服务名、接口签名和配置条目均为拟定设计，不代表当前已经可调用。实施前需评审明确标出的产品建议。

| 已确认需求 | 开发约束 |
|---|---|
| 一个项目对应一个工作空间 | 复用 WorkspaceId 与会话归属，不再维护另一套项目身份注册表。 |
| 独立的项目管理插件 | 提供独立页面与可单独挂载的插件条目。 |
| 用户不填写目录路径 | 在配置的绝对项目根目录下自动创建。 |
| 项目根目录使用绝对路径 | 在 `feishu.patch.yml` 配置为 `/Users/think/.dsh/projects`。 |
| 所有项目先对大家可见 | 当前部署所有已登录用户均可见项目元数据；不新增组织表、项目成员表。 |
| 不维护元数据修订号 | 不增加 revision、expectedRevision 或基于 ETag 的编辑锁。 |
| 增加项目阶段 | 持久保存第 4 节的九种稳定阶段代码之一。 |

以下内容用于补全实施方案，属于建议规则，尚未单独确认：管理员创建、编辑、归档、恢复项目；普通用户浏览并在项目中工作；项目文件共享而会话仍由创建人拥有；归档保留数据并限制新活动；项目名称在项目之间唯一。菜单建议放在「数字员工」上方。

第一版不包含：项目级成员权限、跨组织共享、元数据修订历史、合同文档流转、回款开票、审批引擎、自动推进阶段、任意目录导入、永久删除数据，以及多个 Host 并发写入。

### 3. 插件分层与职责

| 拟定包 | 职责 |
|---|---|
| `packages/workspace/project` → `@deepseek-ai/dsh-project` | Host project service / Host 项目业务服务，`ctx.projects`。 |
| `packages/api/project-controller` → `@deepseek-ai/dsh-api-project-controller` | Typed Remote commands and project feed / 类型化 Remote 命令与项目订阅，`ctx.remote.project`。 |
| `packages/client/ui-projects` → `@deepseek-ai/dsh-client-ui-projects` | Project list, details and forms / 项目列表、详情与表单。 |

WorkspaceRegistry 拥有全部持久 Workspace 记录、项目属性、注册顺序与会话归属。项目服务负责名称与阶段校验、项目生命周期和目录创建，通过显式注册表方法操作。禁止二次打开 workspace domain、经诊断句柄写入或另存一份项目列表。创建时必须一次发布完整项目记录，不能先创建并发布普通工作区，再通过第二次写入补上项目属性。

创建人 ID 的共享类型必须放在 workspace 与账号包都可引用的身份类型模块中。必要时移动已有 WebUserId 声明并由原入口重导出；不能让工作区核心依赖已经引用 workspace 的 client-connection，形成编译循环。schema 与品牌化 ID 应可用于 Host 及生成的客户端类型，不导入服务端运行时代码。

项目订阅与工作区订阅必须在完整注册表操作提交后发布，包含注册顺序与恢复状态。不能把每条底层 domain/changed 通知直接翻译为公开的创建成功；当前后端没有跨记录事务，还可能发生补偿写入。若现有订阅不能安全观察完整提交，应增加注册表拥有的提交后通知。

将账号的工作区访问判断集中到一个访问服务，或显式扩展已有账号服务，覆盖个人归属、项目元数据管理、项目使用与路径访问，各控制器统一调用。账号身份和会话所有权继续由 webAccounts 拥有；不能用最后一次浏览器请求的身份为其他订阅者过滤数据。

### 4. 元数据与项目阶段

使用现有 workspace 存储领域。记录键仍为 WorkspaceId，记录保留 path、title、sessionIds、createdAt、updatedAt，增加以下可选 project 对象。没有该字段的已有普通或个人工作区，不会自动成为公开项目。

```json
{
  "description": "项目背景、建设目标和服务范围",
  "createdBy": "<WebUserId>",
  "status": "active",
  "stage": "engagement"
}
```

description 为可为空的字符串；createdBy 为从服务端认证身份取得的品牌化 WebUserId，创建后不变；status 仅为 active 或 archived；stage 为必填枚举。名称只保存在 Workspace.title，不重复保存 project.name。不增加 projectId、organization、members、revision，也不给每个用户保存 projectIds 数组。

时间戳沿用 Workspace 的 ISO-8601 字段。修改项目属性会更新 updatedAt，会话归属变更也可能更新它，因此不能将其当成阶段变更时间或审计历史。删除账号不能级联删除项目，也不能使历史创建人 ID 失效；无法解析当前账号名称时显示创建人 ID。

| 代码 | 中文名称 | 主要工作与推进参考 |
|---|---|---|
| engagement | 项目接洽 | 建立联系、了解合作意向；明确对接人并安排调研。 |
| discovery | 需求调研 | 了解教育需求、学校、服务对象与资源，明确范围和限制条件。 |
| proposal | 方案论证 | 编制建设与运营方案，沟通服务内容、投入和预期成果。 |
| approval | 立项与采购推进 | 配合推进项目决策、资金安排与适用的采购流程。 |
| contracting | 合同洽谈与签署 | 确认双方责任、服务范围、交付标准和商务条款，完成签约。 |
| preparation | 建设筹备 | 准备场地、课程、师资、设备、平台与运营团队。 |
| pilot | 试点运行 | 小范围开展服务，评估课程、组织与平台流程，完成整改。 |
| acceptance | 验收交付 | 按约定检查交付成果，完成验收及交接材料。 |
| operation | 正式运营 | 持续开展服务，跟踪质量和效果，推进后续合作。 |

新项目默认 engagement。管理者可以跳转或回退阶段；阶段变更不会执行政府流程，也不表示法律程序已经完成。归档独立于阶段，恢复时保留原阶段。已有工作区转为项目时，必须显式选择阶段，不推测其推进进度。

持久读取与外部输入都必须经过 Zod 校验。更新操作在注册表队列内读取最新记录，只替换明确提交的项目字段，保留 sessionIds 与其他值，持久化成功后才发布变更。不检查修订号，同一字段以最后一次提交成功的值为准。

### 5. 配置与项目目录

以下为实施后追加到 feishu.patch.yml 的拟定配置片段。保留现有 connection 配置；若 patch 条目整体替换 config，必须完整保留原条目所需字段。

```yaml
- id: projects
  name: '@deepseek-ai/dsh-project'
  config:
    root: /Users/think/.dsh/projects
- id: project-controller
  name: '@deepseek-ai/dsh-api-project-controller'
- id: ui-projects
  name: '@deepseek-ai/dsh-client-ui-projects'
```

root 必填且必须为绝对路径，不解析 ~，不回退到 cwd，也不把这台机器的路径写死在源码中。激活时校验，在支持的系统上以仅所有者可访问的权限创建缺失父目录，取得规范路径；不可用时明确报错。本部署的配置值为 /Users/think/.dsh/projects。

```text
/Users/think/.dsh/projects/
  <WorkspaceId>/
```

WorkspaceId 由服务端生成并品牌化。项目名称只是显示元数据，不参与路径拼接。规范化后的项目目录必须位于 root 下，不接管已存在的非空目录，也不跟随意外符号链接。项目改名不移动目录。修改 root 属于显式迁移操作，已有路径不能静默移动或重新映射；配置与路径不一致的项目应报告异常，等待修复。

项目文件保存在这些目录中。工作区与项目元数据仍在 storage-domain，会话日志仍在 Session persistence。不能把权威注册表、登录凭据或其他用户的会话日志放入共享项目目录。项目目录丢失时应显示不可用及诊断信息，不能删除元数据或静默重建空目录。

### 6. 创建流程与中断恢复

创建顺序：校验调用权限；规范化并校验名称、描述和阶段；串行检查项目名称唯一性；生成 ID；持久记录有限的创建意图；创建所属目录；提交含完整项目属性的 Workspace 记录及注册顺序；完成创建意图；发布已提交状态并返回。创建意图属于内部中断恢复数据，不是产品修订号，也不是第二份项目注册表。应扩展或整合已有注册表的 pending-mutation 机制，避免堆叠不相关的生命周期标记。

建议名称规则：去除两端空白后不能为空，且在全部项目中唯一，包含已归档项目，不与个人工作区名称混为一组。创建和改名使用同一套明确、确定性的比较规则。随部署变化的文本长度限制应为经过校验的插件配置。前端校验不能替代服务端校验。

创建目录失败时，不发布 Workspace。提交元数据失败时，只清理本次创建且仍为空的目录；非空时保留并报告错误。重启后，在暴露新项目之前对照创建意图、已提交注册表和目录完成恢复。禁止递归删除无法确认归属的目录。提交后崩溃必须恢复同一个已提交项目，不能另建一个。

前端提交期间禁用重复提交。第一版遇到网络结果不确定时，不自动重试创建，应刷新项目列表并提示创建可能已成功。名称唯一性可阻止普通的同名重复提交，但不承诺 exactly-once。若后续增加自动重试，需显式设计按调用人隔离的持久请求 ID 回执，不能只使用内存缓存。

### 7. Remote 接口

使用类型化请求和响应、品牌化 ID、生成的 Remote 客户端及稳定错误码。每个修改操作都从服务端取得当前身份与管理员状态。拒绝客户端提供 path、createdBy、organization、revision 或任意 status 值。

| 拟定方法 | 请求 | 返回与行为 |
|---|---|---|
| project.list | status 为 active / archived / all，可选 query、stage | 返回过滤后的完整项目元数据快照，不包含会话 ID 或个人绝对路径。 |
| project.get | workspaceId | 返回单个项目元数据，不存在时 project/not-found。 |
| project.create | title、description；stage 可选 | 持久创建项目，未提供 stage 时使用 engagement；返回已提交项目。 |
| project.update | workspaceId，以及需要修改的 title、description、stage | 只更新提交字段，空 description 表示清空；不能修改 status 或 path。 |
| project.archive | workspaceId | 幂等归档，保留目录、阶段与会话。 |
| project.restore | workspaceId | 幂等恢复，保留阶段。 |
| project.follow | 流取消信号 | 首帧为完整 baseline，随后推送已提交的 upsert/remove；重连替换快照。 |

ProjectView 仅包含 workspaceId、title、description、createdBy、status、stage、createdAt、updatedAt。若需目录诊断，应作为管理者详情另行提供。第一版不提供 delete 接口。未认证调用拒绝；非管理员修改元数据返回 project/forbidden。区分输入无效、名称冲突、项目不存在、已归档、执行繁忙、目录不可用与存储故障。写入失败不能发出成功变更。

### 8. 可见性、会话与文件访问

当前可见工作区由「当前用户的个人工作区 + 所有 active 项目工作区」动态计算。项目对本部署所有已登录账号可见，不使用组织字段或成员清单。已归档项目通过显式归档视图查看。不能将任意历史普通工作区或其他用户的个人工作区一起公开。

建议访问规则如下：

| 操作 | 普通用户 | 管理员 |
|---|---|---|
| 查看项目元数据与共享文件 | 允许 | 允许 |
| 创建、编辑、归档、恢复项目元数据 | 不允许 | 允许 |
| 在 active 项目中新建会话 | 允许，归自己所有 | 允许，归自己所有 |
| 读取他人会话 | 不允许 | 不因管理员身份自动获得权限 |
| 访问他人个人目录 | 不允许 | 不因管理员身份自动获得权限 |

对每个可见项目 Workspace，按持久的会话所有权过滤 sessionIds、数量、摘要、搜索结果、归档列表和子会话目录。baseline、upsert/order 增量以及直接按 ID 查询都必须使用同一规则；不能把所有人的会话 ID 发给浏览器，再由 React 隐藏。每条订阅固定其调用身份，并在项目生命周期变化时重新计算可见范围。

创建会话时允许指定可访问且 active 的项目 WorkspaceId；没有显式工作区时保留个人默认值。cwd 必须由服务端从该 Workspace 解析。会话在可见之前先完成所有权预留与持久提交。分叉和后台子会话继续遵循已有归属规则。数字员工和工作台必须在所选项目中创建会话，不能静默回退到个人目录。

文件授权覆盖调用人的个人目录及可访问项目目录；已有目标校验规范路径，新建目标校验规范父目录。检查文件浏览、上传下载、预览、媒体引用、文件监听、搜索、终端、工具和后台任务。只改 HTTP 校验不能约束 shell/PTY 工具，执行文件系统与沙箱策略必须排除凭据、注册数据及其他用户私有文件。所属操作必须拒绝移动、重命名或删除项目根目录本身，同时允许普通子文件操作。归档状态需按实际目标项目路径判断，包含从其他工作区发起的工具访问。共享项目文件可能被并发修改，元数据串行写入不等于文件锁或版本控制。

### 9. 归档与删除语义

建议第一版归档行为：从默认 active 列表隐藏，拒绝新建会话，历史会话只允许其所有者只读查看。拒绝该归档项目的新模型轮次、排队或后台继续执行，以及修改文件的工具操作。保留目录、日志、ID 与阶段，恢复后重新允许正常使用。管理员仍可修正已归档项目的元数据。

执行准入与归档必须串行协调：若项目存在正在执行的轮次、后台任务、活动终端或不能完成排空的已准入写操作，返回 project/busy，不能在工作仍执行时承诺只读。实际执行时重新检查资格，不能只在 UI 提交时检查。实施时必须说明外部 OS 进程如何处理；应用归档不是操作系统级文件写锁。

通用 workspace.delete、改名和更新路径不能绕过项目生命周期与元数据规则。对项目的修改需路由到所属业务操作，或明确拒绝通用操作。个人工作区仍固定。项目归档与会话归档相互独立，不能通过把全部会话加入全局归档集合来实现项目归档。永久删除目录或日志，以及移除项目注册，均延期。

### 10. UI 与实时状态

独立「项目管理」菜单打开完整主面板。列表卡片或行展示名称、描述、阶段、启用或归档状态、创建人和时间，支持名称与描述搜索、阶段筛选、active 与归档视图。详情展示相同元数据，并提供「进入工作区」。仅管理员显示「新建」「编辑」「归档」「恢复」，服务端仍必须校验权限。

新建与编辑表单只有名称、描述、阶段，不提供路径选择器、修订号、组织或成员选择。完整处理加载、空列表、断线、校验失败、名称冲突与存储错误。保存失败保留草稿，等待已提交响应后才关闭表单。归档确认说明会保留文件和历史会话。

侧栏保留个人工作区并加入可见项目，包含没有会话的空项目。建议单独设「项目工作区」分组，初期按名称与 ID 稳定排序，不新增持久排序表。搜索和分组逻辑不能丢失空项目。个人显示偏好不能复用全局注册表排序接口。

UI 通过 slots 注册并随插件卸载释放，产品文案由中英文字典拥有。共享或需要跨挂载保留的数据放在声明的 store 中。项目管理订阅项目元数据，工作区导航订阅 Workspace 投影，两者都从同一已提交注册表派生，重连各自替换 baseline。不能在 localStorage 中维护乐观更新的权威项目注册表。

### 11. 兼容与开发顺序

旧 Workspace 记录增加可选 project 字段。不改变已有 ID、个人目录、会话归属或已发布的会话日志代际。workspace domain 当前使用 single 布局并拒绝版本不符，不能只提升版本号使已有数据无法读取。可经审查后为有兼容测试的加法 schema 保留领域版本，或先实现受支持的显式迁移再切换版本，并遵循仓库持久化类型变更确认规则。

已有工作区不能自动共享。后续若提供管理员转换功能，必须显式检查目录与 root 规则，选择阶段、确定创建人规则，并核查历史会话所有权。转换与导入不属于第一版。服务挂载时不能扫描任意目录并推断它们是项目。

建议顺序：工作区元数据与原子注册表操作；项目目录创建和恢复；统一访问判断及会话与文件集成；类型化项目控制器和订阅；工作区订阅改造；UI 插件；profile 与 overlay 接线；兼容证据和端到端验证。不能只改侧栏就交付一个只完成部分共享规则的个人账号模式。

移除项目 UI 或卸载项目服务时，不能将持久项目记录重新解释为普通工作区，或绕过访问规则。保留项目分类，明确拒绝暂不可用的项目操作，同时保持个人工作区可用。

注册新包别名、项目引用、解析器依赖与客户端 manifest。Host 与 Client 编译必须分开：启动 Host 的浏览器 e2e 用例应加入 tsconfig.host.json，并从 apps/web/tsconfig.json 排除。由各生成器更新受影响目录，并维护双语配对记录。

## 验收标准

每项都需要真实应用组合中的可观察证据，失败分支补充聚焦单元测试。双账号浏览器场景必须使用不同的已认证浏览器上下文，不能用模拟过滤器替代。

1. 加载 overlay 后使用 /Users/think/.dsh/projects；缺失、相对或不可用 root 明确失败；表单与 API 均不能指定任意项目路径。
2. 管理员创建项目后，出现一个完整项目 Workspace 及其目录；两个用户无需刷新都能看见空项目，各自个人工作区仍私有。
3. 名称、描述和九种阶段重启后保留；改名不改变目录与 ID；阶段可跳转和回退，归档与恢复保留阶段。
4. 按建议角色规则，非管理员直接调用修改 RPC 被拒绝；同名、非法阶段、不支持字段和越出 root 的路径均由所属操作拒绝。
5. 并发修改项目及关联会话时，保留无关字段与会话归属；写入失败不改变权威内存，也不发成功通知。
6. 目录失败、元数据失败，以及创建意图、目录创建、提交各点中断，均能恢复；不留下虚假可见项目，不误删目录，不重复创建已提交项目。
7. 两个用户均能处理共享项目文件；各自只看见自己的项目会话，不能从其他接口取得他人的会话 ID、摘要、订阅、个人目录文件或子会话目录。
8. 项目会话创建、数字员工启动与工作台启动都使用所选项目 cwd；未指定工作区的普通创建仍使用个人默认目录。
9. baseline、增量、重连、退出再登录遵循相同访问规则；项目改名、归档与恢复同步更新项目管理与工作区导航，包含当前选中的项目。
10. 按建议规则，归档繁忙项目被拒绝；归档提交后阻止新活动且保留文件和日志；会话归档不会归档项目，通用 Workspace API 不能绕过项目规则。
11. 旧工作区数据可读取，不被强制公开，不重写会话日志；目录丢失可诊断；修改 root 不会触发自动迁移。
12. UI 具备本地化加载、空列表、错误状态和筛选；卸载插件会移除 slots、订阅与 effects，未完成导航不能重新打开已离开的页面。
13. 新浏览器测试归入正确编译程序，完整客户端构建与 Host 类型检查通过；运行聚焦后端和 Loader 测试、GUI 测试、无密钥浏览器快照及必要持久化和文档检查，记录实际命令并区分既有失败。

开发交付包含三个包、全部受影响调用方、fixture 与预期输出、README 双语配对、更新后的决策记录、配置接线、持久化兼容证据与双用户演示。仅完成项目管理页面不满足本方案。

## 考虑过的替代方案

**独立 Project 表与身份**会重复一个项目对应一个工作区的关系，使名称、路径和删除需要跨记录同步，因此扩展已有 Workspace 记录。

**为每个用户复制项目列表**使每次创建、归档都需要批量写入及失效列表恢复，因此从共享注册表派生可见工作区。

**从目录名称或目录内 JSON 推导项目身份**会使改名、目录丢失及共享文件编辑影响管理身份，因此使用稳定 ID，并由 storage-domain 保存权威元数据。

**修订号编辑与组织成员表**不属于已确认的第一版范围，本版使用串行字段更新及部署范围内的统一项目可见性。

账号设计继续拥有登录与会话归属；本方案仅在挂载项目能力时调整其「唯一个人工作区」限制。存储与工作区设计继续拥有持久化职责。相关既有记录仍有独立适用范围，本提案不取代或归档它们。

## 风险

- 创建与编辑的管理员规则、会话私有规则、归档限制及菜单位置需在实施前确认，不能将项目元数据全部可见理解为全部会话公开。
- 共享目录中的文件变更会影响其他用户，元数据排序不能解决并发编辑文件的问题。产品文案需说明共享属性，执行权限必须与宣称范围一致。
- 没有修订号时，并发修改同一字段可能覆盖先前值。第一版接受这一行为，不隐含审计或历史系统。
- 文件系统创建与元数据不在同一事务中，必须具备持久恢复意图和故障注入测试，仅实现顺利路径的 mkdir 加 put 不够。
- 建议归档规则涉及控制器、任务、工具和终端。若第一版无法可靠实现准入与排空，应经产品确认收窄归档语义，不能静默宣称已经只读保护。

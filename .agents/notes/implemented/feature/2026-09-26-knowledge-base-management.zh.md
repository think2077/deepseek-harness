# Agent Note: Knowledge-base management page

Status: implemented

[English](2026-09-26-knowledge-base-management.md) | 中文

## Problem

方案专属知识存放在专家可直接维护的本地文件中，但 DSH 没有安全的浏览器界面来发现和编辑这些文件。项目证据也存放在各 Workspace 下，它们需要可见，同时不能让全局管理界面修改任务源材料。

## Decision

一个独立 Host 插件在部署配置的知识根目录与 Workspace 派生的项目根目录上拥有 `knowledgeBase` Remote namespace。公共知识库与方案专属知识库根目录可以设为可写。随附 Web 组合还会把候选知识配置为只读根目录，让专家可以查看候选材料，同时不把第一期扩展为审核流程。每个已注册 Workspace 都把配置的项目知识子目录贡献为只读根目录。文件继续作为事实来源；DSH 不把它们复制到数据库，也不建立持久索引。

Host 列出受支持的文本文件、读取一份文档，并且只在可写且非项目型根目录中创建、替换或移除文件。替换与移除要求调用方携带其打开内容的 SHA-256 revision。DSH 写入方使用每目标文件锁；已接受的更新会原子执行并保留文件 mode，创建使用排他写入，移除则把文件重命名到隐藏的可恢复回收目录。Host 隐藏绝对路径、拒绝穿越路径与位于根目录之外的规范路径，并强制所有项目根目录只读。

一个独立 Client 插件在新会话上方贡献本地化的知识库入口，并注册匹配的完整尺寸主面板。知识库标签把公共知识库、方案专属知识库与候选知识放在树中，项目信息标签则单独展示 Workspace 资料。选择文件后直接打开 Markdown 预览或文本编辑器。可写根目录支持创建 Markdown 与确认后可恢复移除；只读根目录隐藏所有修改操作。controller 采用 Host 返回的 revision，并在 Host 报告冲突时保留本地状态。

## Alternatives considered

**把知识存入新数据库。** 未采用，因为现有文件已经由技能消费，并可用普通文件工具维护。第二份持久表示会引入同步与迁移，却不能改善第一期流程。

**让浏览器直接读取本地文件。** 未采用，因为浏览器文件访问无法一致执行部署根目录约束，还会把 Host 路径与权限暴露给 UI 代码。

**允许从全局面板修改项目知识。** 未采用，因为任务证据属于 Workspace 工作流。全局管理页面可以查看，但不能成为项目源材料的第二个编辑入口。

**自动合并冲突文本。** 第一期未采用，因为通用三方合并无法验证 Markdown、YAML 与 JSON 语义。页面会保留草稿并明确提示冲突。

## Consequences

专家可以从专用主面板维护公共知识库与方案专属知识库，并查看候选知识，同时保留现有技能的文件兼容性。树形筛选保留磁盘上的分类层次。注册 Workspace 后会在单独标签中自动暴露其项目知识目录，无需机器专属配置，而且项目条目保持只读。浏览器打开的 revision 已过期时，并发或外部编辑会被发现。重命名、移动、界面内回收恢复、文件系统监听、会话萃取和候选审核仍不属于本期范围。

# Agent Note: Knowledge-base management page

Status: implemented

[English](2026-09-26-knowledge-base-management.md) | 中文

## Problem

方案专属知识存放在专家可直接维护的本地文件中，但 DSH 没有安全的浏览器界面来发现和编辑这些文件。项目证据也存放在各 Workspace 下，它们需要可见，同时不能让全局管理界面修改任务源材料。

## Decision

一个独立 Host 插件在部署配置的知识根目录与 Workspace 派生的项目根目录上拥有 `knowledgeBase` Remote namespace。公共知识库与方案专属知识库根目录可以设为可写。随附 Web 组合把候选知识配置为通用操作只读的根目录，并为专用审核流程配置待审核、已采纳和已拒绝目录。每个已注册 Workspace 都把配置的项目知识子目录贡献为只读根目录。文件继续作为事实来源；DSH 不把它们复制到数据库，也不建立持久索引。

Host 列出受支持的文本文件、读取一份文档，并且只在可写且非项目型根目录中创建、替换或移除文件。替换与移除要求调用方携带其打开内容的 SHA-256 revision。审核操作单独允许编辑待审核候选并进行目录流转，但不会让候选根目录整体变成可写。采纳前，审核人可以从当前会话启动一个已记录的一次性子会话，请求结构化合并建议。该子会话显式调用配置的合并技能，比较候选知识与所选目标的最新内容，再返回插入、追加、替换或跳过判断及完整草案，但不能提交结果。采纳要求候选 revision 与建议分析时的目标 revision。Client 发送审核人确认过的目标文件全文；Host 在修改阶段不做语义推断，只写入这份确认文本。DSH 写入方会锁定两个文件，并在候选归档失败时回滚目标。Host 隐藏绝对路径、拒绝穿越路径与位于根目录之外的规范路径，并强制所有项目根目录只读。

一个独立 Client 插件在新会话上方贡献本地化的我的审核与知识库入口，并注册匹配的完整尺寸主面板。我的审核用待审核、已采纳和已拒绝标签展示候选卡。每张卡只展示一段易读的知识建议，技术依据保持隐藏。待审核卡支持修改这段建议、确认拒绝与确认采纳。采纳表单把有效的 `suggested_destination` 映射到已配置根目录与路径，也允许审核人修改两者；界面展示智能处理方式、目标章节、说明与完整可编辑 Markdown，并在建议生成完成之前禁用最终操作。知识库保留公共、方案专属、候选与项目文件视图。Host 报告冲突时，两个 controller 都会保留本地状态。

## Alternatives considered

**把知识存入新数据库。** 未采用，因为现有文件已经由技能消费，并可用普通文件工具维护。第二份持久表示会引入同步与迁移，却不能改善第一期流程。

**让浏览器直接读取本地文件。** 未采用，因为浏览器文件访问无法一致执行部署根目录约束，还会把 Host 路径与权限暴露给 UI 代码。

**允许从全局面板修改项目知识。** 未采用，因为任务证据属于 Workspace 工作流。全局管理页面可以查看，但不能成为项目源材料的第二个编辑入口。

**自动应用模型生成文本。** 未采用，因为语义分类可能出错，而且共享规范会影响后续任务。模型只生成尚未生效的草案，审核人确认后才提交；若目标在分析后发生变化，revision 校验会拒绝写入。

**让萃取技能直接批准并写入知识。** 未采用，因为分类具有概率性，而一次合并会改变所有后续任务共享的指导。萃取可以提出 `suggested_destination`，但只有审核页面可以提交用户确认过的目标与最终文件。

## Consequences

专家可以从专用主面板维护公共知识库与方案专属知识库，并处理候选知识，同时保留现有技能的文件兼容性。树形筛选保留磁盘上的分类层次。候选文件会显式流经专家也能在 DSH 外查看的待审核、已采纳与已拒绝目录。萃取与合并技能可以改进建议，但不会获得最终写入权限。合并建议会消耗一次模型请求并要求兼容的活动会话，但其提示与结构化结果会保存在子会话日志中。注册 Workspace 后会在单独标签中自动暴露其项目知识目录，而且项目条目保持只读。浏览器打开的 revision 已过期时，并发或外部编辑会被发现。重命名、通用文件移动、界面内回收恢复、文件系统监听和会话自动萃取仍不属于此能力。
